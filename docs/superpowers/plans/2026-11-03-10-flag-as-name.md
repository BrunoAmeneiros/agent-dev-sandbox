# Un flag no es un nombre: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Si el primer argumento empieza por `--` después de quitarle los espacios, la CLI imprime el texto de uso en lugar de saludarlo (`greet --shout Ana` no debe imprimir `Hello, --shout!`).

**Architecture:** En `GreetingCli.run` se quitan los espacios a `args[0]` una vez y el resultado se usa para todo: la comprobación de nombre en blanco, la nueva comprobación del prefijo `--` y el saludo. El resto de la lógica, incluido `--shout` solo en `args[1]`, no cambia.

**Tech Stack:** Java 21, Maven, JUnit Jupiter, Checkstyle, SpotBugs.

**Spec:** `docs/superpowers/specs/2026-11-03-10-triage.md` y `docs/superpowers/specs/2026-11-03-10-impact.md`

## Global Constraints

- Texto de uso exacto: `Usage: greet <name> [--shout]`. El código de salida sigue siendo 0, porque `main` solo imprime.
- Solo cuenta el prefijo `--`, no `-` (decisión de Bruno). Primero se quitan los espacios y luego se mira el prefijo (decisión de Bruno).
- Que los flags valgan en cualquier posición queda fuera: `--shout Ana` **no** grita.
- Rutas protegidas, aprobadas con este plan, que no se modifican: `src/test/java/sandbox/GreetingCliCharacterizationTest.java`, `tests/acceptance/FlagAsNameAcceptanceTest.java` y los tests de aceptación anteriores.
- `mvn -B verify -Pacceptance` y `mvn -B checkstyle:check spotbugs:check` deben pasar. Cobertura de al menos el 80 % del código que cambia.

## Review Focus

- Un guion simple delante (`-x`) sigue siendo un nombre: `Hello, -x!`. Lo fija `singleDashIsStillAName`.
- Un `--` solo, sin más texto, también es un flag y da el texto de uso. Lo fija `doubleDashAlonePrintsUsage`.
- Un `--` en medio o al final del nombre (`Ana--`) sigue siendo un nombre. Lo fija `innerDoubleDashIsStillAName`.
- `--shout` detrás de un nombre sigue gritando. Lo fija la caracterización (`shoutsWhenSecondArgumentIsShout`).
- Espacios delante del flag (`"  --shout"`) dan el texto de uso. Lo fija `FlagAsNameAcceptanceTest.flagWithLeadingSpacesPrintsUsage`.
